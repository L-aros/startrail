# 冲突处理

冲突的定义是同一实体在共同祖先后出现多个非祖先 revision。时钟用于提示，不用于自动覆盖。

| 内容 | 默认行为 | 用户选择 |
|---|---|---|
| 条目正文/元数据 | 保留 sibling，时间线标记“需要处理” | 保留 A、保留 B、手工合并并创建新 revision |
| 附件集合 | 合并不同 blob；同 ID 内容不同则 sibling | 选择/保留全部 |
| 删除 vs 修改 | 保留修改与 tombstone，提示 | 恢复或确认删除 |
| 标签 | 按 UUID 合并；同规范化名称提示重命名 | 重命名/合并 |

解决冲突会创建新对象和 merge manifest，不删除历史。所有设备均看到该新版本；未解决冲突仍可安全同步。冲突 UI 必须在写出前展示两个版本的创建设备、时间、内容差异（本地计算）。
